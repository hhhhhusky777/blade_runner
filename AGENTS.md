# Project agent entry point

Read the [project README](README.md),
[adoption manifest](.github/spec-driven-delivery/project-adoption-manifest.md),
[solution whiteboard](.github/spec-driven-delivery/solution-whiteboard.md), and
applicable [project experience](docs/experience.md).

Use the verified installer-generated `.sdd-runtime/agent-guide.md` and its
managed skill. If missing, obtain `install-sdd.sh` from the manifest's playbook
repository at its full pinned revision, run it from this root, then validate.
The manifest indexes the installed Engineering Knowledge Base.

Preserve existing work and follow the owner's current instructions. Adoption
does not authorize game-task creation or submission, source-code email, remote
publication, or Git merges. Keep credentials out of tracked files and archives.

The manifest owns installation and stable authority; the whiteboard owns normal
delivery design; an implementation plan, when present, owns active delivery
state. Read the manifest for current adoption state; obtain owner acceptance
after two independent agent reviews before activating the workflow. Do not
infer a solver implementation task from installation or prior exploratory
discussion.
